## 2. 파이프라인 단계별 세부 정의 및 명세

### Process 1: PPTX Input Parsing
- **정의**: 상품화 심의회 등 설계 변경 이력이 포함된 PPTX 프리젠테이션 파일로부터 정제된 텍스트 및 사양 테이블 데이터를 안전하게 파싱하는 전처리 단계임.
- **입력**: 상품화 개발 등급 확정 심의회 PPTX 파일
- **출력**: 취소선 텍스트가 필터링되고 글자 굵기(Bold) 속성이 추출된 텍스트 청크 리스트 및 모듈별 사양 테이블 데이터
- **수행 역할**:
    - 슬라이드 내 모든 셰이프와 표(Table) 객체를 재귀 순회하며 텍스트를 로드함.
    - 취소선(`strike`) 서식이 그어진 텍스트는 변경 대상에서 제외하고 삭제 처리함.
    - 굵게(`bold`) 표시된 기술적 지표(예: 신규 모터 모델명, 치수 등)는 의미적 가중치 단어로 별도 태깅함.
- **목적**: 분석 단계 이전에 PPT 데이터 내 취소선에 의한 노이즈를 필터링하고 핵심 키워드를 강조하여 매칭 정확도를 원천적으로 높이기 위함임.

### Process 2: Query Expansion
- **정의**: 파싱된 개별 자연어 변경 설명글을 LLM을 통해 의미적으로 보완하고 기계적 매칭을 수행할 수 있는 다양한 동의어 및 연관 키워드군으로 확장하는 단계임.
- **입력**: PPT 상세 사양 테이블에서 추출된 개별 변경 기술 문장(자연어 쿼리)
- **출력**: 구조화된 쿼리 확장 데이터 (Target Assembly 명칭, 동의어 리스트, 연관 기구 부품 키워드 리스트, 변경 행동 방식)
- **수행 역할**:
    - LLM에게 해당 변경 문맥(예: "AC 모터에서 BLDC 모터로 변경")을 파악하도록 프롬프트 처리함.
    - 이에 수반되어 교체되거나 추가되어야 하는 기구 및 하네스 부품들(예: harness, bracket, fan, blade 등)의 키워드를 AI 추론으로 도출함.
- **목적**: 설계자가 입력한 짧은 자연어 텍스트와 실제 BOM 마스터 엑셀에 축약어로 기재된 품명 간의 용어적 불일치를 해소하여 검색 재현율(Recall)을 극대화하기 위함임.

### Process 3: Self-Verification
- **정의**: 확장된 쿼리 결과가 사전에 정의된 BOM 도메인의 엄격한 설계 규칙(Make/Buy 룰 등)과 모순되지 않는지 LLM 가드레일을 통해 스스로 검증하고 정제하는 단계임.
- **입력**: 1차 쿼리 확장 JSON 데이터 및 원본 변경 쿼리
- **출력**: 정합성 검증 판정 결과 (is_valid: true/false, 검증 논리적 사유, 정제된 최종 JSON)
- **수행 역할**:
    - 대상 품목이 국내구입(G)/해외도입(D) 등의 Buy 품목인지, 사내자작(T)/협력사조립(S) 등의 Make 품목인지 판별함.
    - 설계 가이드라인에 위반되는 행위(예: Buy 품목인데 하부 부품만 부분 대체하도록 설계하는 경우 등)가 감지되면 LLM 가드레일을 통해 JSON 행동 방식을 안전하게 보정함.
- **목적**: LLM 호출 과정에서 발생할 수 있는 환각 현상(Hallucination) 및 설계 모순을 방지하여 매칭 및 추천의 기술적 신뢰성을 확보하기 위함임.

### Process 4: BOM Tree Restoration
- **정의**: 엑셀에 선형 리스트 형태로 저장되어 있는 부품 리스트의 BOM Level 깊이 정보를 해석하여 트리 구조의 부모-자식 계층 관계를 인메모리 상에 완벽히 복원하는 단계임.
- **입력**: Base BOM 엑셀 파일 및 Master 개발부품 엑셀 파일
- **출력**: `NetworkX DiGraph`로 구축된 인메모리 유향 그래프 및 부모-자식 관계 맵
- **동작**:
    - Master 시트의 `BOM Level` 열에 표기된 점(.)의 개수를 기준으로 트리 깊이(Depth)를 계산함.
    - 선형 탐색 시 깊이가 깊어지면 자식으로, 얕아지면 스택에서 팝(Pop)하여 현재 깊이의 바로 상위 부모 노드를 식별해 엣지(Edge)를 연결함.
- **목적**: 특정 하위 단품(Leaf Node)이 바뀔 때 그 영향이 상부 어셈블리(Assembly)로 연쇄 전파되는 경로를 추적하기 위한 기초 트리 그래프 아키텍처를 제공하기 위함임.

### Process 5: Pinpoint Node Matching
- **정의**: PPT의 상세 변경 조건 및 LLM 쿼리 확장 키워드를 기반으로, 마스터 엑셀 내에서 실제로 교체되거나 수정되어야 하는 최적의 타겟 단품 노드를 판별하여 매칭하는 단계임.
- **입력**: 복원된 마스터 트리 노드 메타데이터 및 검증 완료된 쿼리 확장 키워드 데이터
- **출력**: 변경 대상 부품으로 마킹된 마스터 데이터 행 인덱스 및 상세 사유
- **수행 역할**:
    - 1차적으로 특정 품번 및 명확한 키워드 룰(Rule) 매칭을 수행해 확실한 부품들을 우선 지정함.
    - 2차적으로 LLM 정밀 매칭(`match_target_node_with_llm`)을 수행하여 텍스트 유사도가 낮은 부품들도 도메인 기능적 관점에서 후보군 중 최적의 매칭 대상을 선정하고 매칭 스코어를 매김.
- **목적**: 정형화된 단순 변경은 고속의 룰 기반으로 매칭하고, 모호한 자연어 맥락은 LLM 매칭을 결합하여 매칭 정확도(Precision)를 극대화하기 위함임.

### Process 6: Change Propagation
- **정의**: 매칭이 완료된 하위 단품 변경 노드들의 영향도를 부모 노드 방향으로 역추적하여, 상위 어셈블리들의 변경점 정보를 자동으로 연쇄 갱신하는 단계임.
- **입력**: 변경 마킹된 마스터 단품 노드 리스트 및 트리 계층 데이터
- **출력**: 상부 노드들의 변경점(J열) 및 변경사유(K열)가 자동으로 상속 및 마킹된 마스터 데이터셋
- **수행 역할**:
    - 가장 깊은 자식 노드부터 시작하여 부모 노드를 추적하며 역방향(Bottom-up)으로 전파함.
    - 자식의 변경 사항이 감지되면 부모의 변경점을 `하위 부품 변경`으로, 변경사유를 `하위부품 변경`으로 자동 세팅함.
    - 이때, 부모 노드 자체가 고유의 설계 변경 사유(예: Conv Heater 높이 변경 등)를 이미 가지고 있다면 값을 덮어쓰지 않고 유지하도록 보호함.
- **목적**: 하부 설계 변경이 상위 모듈 전체의 도면 수정 및 인증 시험 등에 영향을 미친다는 BOM 도메인 영향도 상속 규칙을 계형화하여 자동으로 반영하기 위함임.

### Process 7: Formatted Excel Write
- **정의**: 모든 변경 데이터 및 전파 정보의 계산이 끝난 후, 원본 마스터 엑셀 파일의 복잡한 서식(다중 셀 병합, 스타일, 수식 등)을 완벽히 보존한 채 데이터만 안전하게 덮어쓰기하여 저장하는 단계임.
- **입력**: 변경점 및 전파 로직이 적용된 최종 인메모리 마스터 행 데이터
- **출력**: 기존 양식과 색상이 깨지지 않고 셀 값만 업데이트된 `통합 개발부품Master Compact v1.1.xlsx` 파일
- **수행 역할**:
    - `openpyxl` 라이브러리로 원본 템플릿 파일을 로드함.
    - J열(변경점), K열(변경사유), F열(New P/No), M열(Classification) 등 사전에 약속된 데이터 열 영역만 핀포인트로 값을 기록하고 덮어써서 저장함.
- **목적**: 일반적인 pandas 내보내기 시 손상되는 병합 셀 구조와 스타일 유실을 완벽히 방지하여 현업 실무자가 후가공 없이 즉시 문서를 활용할 수 있도록 지원하기 위함임.
