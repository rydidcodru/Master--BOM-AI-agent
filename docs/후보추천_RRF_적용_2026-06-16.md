# 후보 추천(recommend_change_candidates) — dense+parts RRF 적용

작성일: 2026-06-16 · 대상: `src/dev_parts_backend/workflow.py` `recommend_change_candidates`
근거: BOM 후보검색 ablation(lg Postgres/BGE-M3 67구성 + 이 백엔드 SQLite/OpenAI 교차검증)

## 0. 한 줄

후보 추천 검색을 **dense(combined 임베딩) + parts(부품명/품번 정체) 2채널 RRF**로 교체.
change-text BM25/intent/synonym 채널과 **하드 prefix 게이트를 제거**(→ soft 가산점).
**오직 `recommend_change_candidates` 1개 함수만 변경**(반환 계약·API·프론트 불변).

## 1. 무엇을 바꿨나

| 항목 | 기존 | 신규 |
|---|---|---|
| 융합 | 6채널 가중합(`hybrid_score`) | **RRF(k=60)** 2채널 동등가중 |
| 채널 | dense 4필드 + module/part BM25 + **change BM25 + change-intent(synonym) + identity-text** | **dense(combined)** + **parts(part_name 임베딩·part/no BM25·토큰겹침의 max)** |
| 후보 풀 | `candidate_history_rows` = **하드 prefix LIKE 필터** | `history_rows` = **전체 코퍼스**(prefix는 soft 가산점만) |
| 포함 게이트 | 다중 임계(`include_candidate`) | rrf>0(완화) + exact 강보너스 |
| LLM 재정렬 | 없음 | 없음(유지) |
| 회수 깊이 | `limit`(기본 5) | 동일(`limit`/top_k가 최대 recall 레버 — 키우면 recall↑) |

미사용이 된 헬퍼(`hybrid_score`/`change_bm25_scores`/`change_intent_text_score`/
`candidate_history_rows`/`include_candidate`/`description_match`)는 **삭제하지 않고 보존**(타 경로 비파괴).

## 2. 왜 (ablation 근거)

- **dense+parts가 최강, change-text lexical은 회수 희석** — lg에서 dense+parts 25/68 vs 4채널 full 15/68.
- **하드 게이트가 정답을 통째로 제외** — 이 백엔드 `검색정확도_골든셋_Level_A` 보고서: prefix 게이트가 found@10 **1.00→0.66**(정답 16/47 제외). soft 가산점이면 정답 보존.
- **깊은 회수가 최대 recall 레버**(보편). LLM 재정렬은 lg에서 recall 저하(30→24)라 미도입.

## 3. 효과 (교차검증, cross-model 동일부품 회수, N=339)

| | recall@1 | recall@5 | recall@10 | MRR |
|---|---|---|---|---|
| 기존 | 0.791 | 0.826 | 0.850 | 0.807 |
| **신규** | **0.923** | **0.982** | **1.000** | **0.949** |

## 4. 주의 / 레짐

- parts 채널은 **질의가 부품 식별자/이름을 담을 때** 강하다(=실제 추천 입력). 변경이 부품을 지칭하므로 이 규범에 적합.
- 질의가 과거 텍스트와 거의 동일한 self-retrieval에서는 lexical exact-match가 강하지만, 추천 규범이 아니므로 기본 off 유지(의미는 dense에 포함).
- 회수를 더 원하면 호출측 `top_k`를 5→10~15로. precision과 트레이드오프.
- prefix가 **대용량 다모델 history**에서 노이즈 억제로 유효할 수 있으나, 하드 제외 대신 soft 가산점으로 회수 손실을 막는다(보고서 4-1 권고와 일치).
