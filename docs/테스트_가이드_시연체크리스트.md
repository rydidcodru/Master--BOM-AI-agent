# 테스트 가이드 (시연 체크리스트)

작성일: 2026-06-12
목적: 지금까지 구현한 기능이 잘 동작하는지 **순서대로 따라 하며** 확인한다.
각 항목의 `[ ]`를 직접 체크하고, 기대 결과와 다르면 그 단계를 알려주면 된다.

준비된 샘플 데이터:
- PPTX: `data/input/260309 퀵존레인지 개발등급확정심의회 V5(회의록포함).pptx`
- Base BOM 엑셀: `data/input/base_bom.xlsx`

## 1. Design Points BOM 표 추출 (PPTX 표 → CSV, LLM 안 씀 = 무료)

목적: PPTX의 Design Points 표를 그대로 CSV로 뽑는다.

절차 (Streamlit "변경 입력 및 추천" 탭):
1. PPTX 업로드 칸에 퀵존 PPTX를 드래그앤드롭.
2. **"Design Points BOM 표 추출(충실한 덤프)"** 펼치기 → "PPTX에서 Design Point BOM 추출" 클릭.

기대 결과:
- [ ] "표 13개 / 행 253개 / Design Point 11그룹" 비슷한 요약이 뜬다.
- [ ] 표 미리보기에 `no / lev / base_part_no / new_part_no / part_name / qty / change_point` 컬럼이 보인다.
- [ ] `New P/No` 자리에 `TBD`, `←`, `삭제` 같은 원문이 그대로 보인다.
- [ ] "Design Point BOM CSV 다운로드" 버튼으로 CSV가 받아진다.

---

## 2. PPTX 변경점 LLM 추출 (OpenAI 사용 = 약간의 비용)

목적: PPTX에서 변경 항목을 "한 행 = 한 변경"으로 깔끔히 추출한다.

절차:
1. 같은 탭에서 "LLM 추출" 체크 ON, 모델은 기본값(gpt-4.1-mini).
2. "PPTX에서 변경 입력 추출" 클릭 → 잠시 대기(수 초~십수 초).

기대 결과:
- [ ] "수십 개 변경 입력을 추출해 표에 채웠습니다" (대략 60~70개) 메시지.
- [ ] 아래 "변경 입력 표"에 행들이 채워진다.
- [ ] `change_point`가 길게 뭉치지 않고 **한 변경씩** 들어가 있다.
- [ ] `base_part_no`에 모델코드(BO24 등)가 아니라 진짜 부품번호이거나 비어 있다.

> 비용을 아끼려면: 한 번 추출한 뒤 표가 채워지면 이 단계는 다시 안 해도 된다.

## 3. 변경점 추천 (매핑 정밀 필터 + 성능)

목적: 변경 입력을 과거 이력과 매칭해 후보를 뽑는다. 다른 종류 부품이 섞이지 않아야 한다.

절차:
1. (빠른 확인) 사이드바에서 **"입력 자동 임베딩" 체크 해제**, "연관 부품 수"는 5 정도.
2. 변경 입력 표에서 필요 없으면 행을 줄이고(예: 5~10행) "추천 실행" 류 버튼 클릭.

기대 결과:
- [ ] **타임아웃 없이** 결과가 나온다(수 초 내).
- [ ] 후보 표에 `part_name / 변경사유 / 변경점 / base_part_no / has_change_text` 가 보인다.
- [ ] 예: "Door" 관련 입력의 후보는 전부 Door 계열이고 엉뚱한 부품(Coil/Sheet 등)이 안 섞인다.
- [ ] 변경사유가 비어 있어도 `has_change_text=false`로 표시될 뿐 후보엔 나온다.

간단 검증(선택, 터미널):
```powershell
curl "http://127.0.0.1:8000/health"
```
- [ ] `{"status":"ok"}`

## 4. Base BOM 엑셀 업로드 (회의록 INPUT)

목적: 실제 원본 Base BOM 엑셀을 올려 변경 반영의 기준으로 삼는다.

절차 ("BOM 반영" 탭):
1. "Base BOM 소스"에서 **"원본 엑셀 업로드(base_bom.xlsx)"** 선택.
2. `data/input/base_bom.xlsx` 업로드 → **"Base BOM 불러오기"** 클릭.

기대 결과:
- [ ] "Base BOM 1470행을 불러왔습니다" 메시지.
- [ ] 요약 캡션: 루트 `Electric(Slide)` / 행 1470 / 최대 depth 7 / 대체품 95 비슷하게 표시.

---

## 5. BOM 반영 - 변경(change) + 상향 전파(도미노) (회의록 유형1)

목적: 하위 부품을 바꾸면 상위 Assembly 품번이 TBD(재발행)로 함께 표시된다.

절차:
1. 3번에서 추천을 한 상태여야 후보 선택이 보인다. (없으면 "변경 입력 및 추천"에서 추천 먼저)
2. "BOM 반영" 탭에서 후보 하나 선택, **Action = change**.
3. **"하위 변경 시 상위 Assembly로 전파(도미노)" 체크 ON** (기본 ON).
4. "선택 후보로 BOM 반영" 클릭.

기대 결과:
- [ ] "변경 리스트"에 `change` 1건 + `propagated_change` 여러 건이 보인다.
- [ ] `propagated_change` 행들의 `new_part_no`가 **TBD**로 표시된다.
- [ ] 체크를 OFF로 다시 반영하면 `propagated_change`가 사라지고 `change`만 남는다.

---

## 6. BOM 반영 - 삭제(delete) 트리 삭제 (회의록 유형3)

목적: 부품을 삭제하면 그 하위 부품까지 일괄 삭제된다.

절차:
1. 후보 하나 선택, **Action = delete**.
2. `Target base PNO`에 base BOM에 실제 있는 어셈블리 품번이 들어가 있는지 확인(자동 채워짐).
3. "선택 후보로 BOM 반영" 클릭.

기대 결과:
- [ ] "변경 리스트"에 `delete` 1건.
- [ ] 상단 metric의 **new_bom rows**가 줄어든다(노드 + 하위가 함께 빠짐).

---

## 7. BOM 반영 - 추가(add) + 연동 부품 번들 (회의록 유형2)

목적: 신규 부품을 추가할 때 같이 쓰이던 주변 부품(브라켓/나사 등)을 함께 추천·추가한다.

절차:
1. 후보 하나 선택, **Action = add**.
2. 그 아래 **"함께 추가할 연동 부품(모터→브라켓/나사 등)"** 멀티셀렉트가 나타난다.
3. 추가하고 싶은 연동 부품 1~2개 선택 → "선택 후보로 BOM 반영" 클릭.

기대 결과:
- [ ] 멀티셀렉트에 `[sibling]`/`[descendant]` 표시와 함께 주변 부품 목록이 보인다.
- [ ] "변경 리스트"에 `add` 1건 + 선택한 만큼 `add_bundle` 건이 보인다.
- [ ] new_bom rows가 (1 + 선택 개수)만큼 늘어난다.

---

## 8. 최종 마스터 BOM 다운로드

목적: 반영 결과를 엑셀로 받는다.

절차:
1. 반영 결과가 나온 상태에서 **"new_bom.xlsx 다운로드"** 클릭.

기대 결과:
- [ ] `new_bom.xlsx` 파일이 받아진다.
- [ ] 파일을 열면 `new_bom` / `change_list` / `unmatched` 3개 시트가 있다.
- [ ] `new_bom` 시트에 변경/전파/추가/삭제가 반영된 최종 BOM이 보인다.

---

## 9. (선택) 비용 확인

- [ ] 화면을 가만히 두면(버튼 안 누름) OpenAI 비용은 들지 않는다.
- [ ] 비용이 드는 동작은 2번(LLM 추출), 3번에서 "입력 자동 임베딩" ON일 때뿐이다.
- [ ] 1번(Design Point 추출), 4~8번(Base BOM/반영/다운로드)은 OpenAI를 쓰지 않는다.

---

## 문제가 생기면

- 화면이 옛날 같다 / 새 버튼이 안 보인다 → 서버 재시작(0번).
- 추천이 오래 걸린다 → "입력 자동 임베딩" 끄고, "연관 부품 수" 줄이고, 변경 입력 행 수를 줄인다.
- 후보가 안 나온다 → 변경 입력의 part_name/module명/변경점을 보강.
- 어느 단계든 기대 결과와 다르면 **그 항목 번호**를 알려주면 바로 확인한다.
