# 실행 가이드 (Quickstart)

이 문서는 처음 받은 상태에서 앱이 화면에 뜨고 분석이 돌 때까지의 **end-to-end 셋업 순서**다. 이론·설계 배경은 [python_logic_data_flow_analysis.md](python_logic_data_flow_analysis.md), Graph RAG 내부 구조는 [graph_rag_setup.md](graph_rag_setup.md), 스키마 상세는 [ontology_schema.md](ontology_schema.md) / [schema_analysis.md](schema_analysis.md)를 참고.

---

## 1. 이 앱이 하는 일

**입력**: PPT 변경점 자료 + Base BOM Excel + 과거 개발부품 Master Excel들
**처리**: PPT 파싱 → 변경 의도 추출 → Graph RAG로 유사 변경 이력 검색 → Base BOM 매칭 → 부품 후보 카드 생성 → 사용자 검토/수정
**출력**: 변경부품리스트 Excel + 개발부품마스터 Excel

핵심 구성:
- Streamlit UI ([app.py](../app.py))
- Graph RAG ([graph_rag/](../graph_rag/)) — LlamaIndex KG + Neo4j 기반 검색
- Legacy Chroma 폴백 ([build_rag.py](../build_rag.py), [rag_client.py](../rag_client.py))
- 도메인 모듈: [ppt_parser.py](../ppt_parser.py), [base_bom.py](../base_bom.py), [exporters/](../exporters/), [enrich.py](../enrich.py), [feedback_chat.py](../feedback_chat.py)

## 3. 최초 1회 셋업

### 3.1 의존성 설치

```powershell
# 프로젝트 루트에서
uv sync
```

uv가 가상환경 생성 + 모든 패키지 설치 + lock 동기화. 추가 패키지 (Graph RAG):
- `llama-index-core==0.12.34`
- `llama-index-graph-stores-neo4j==0.4.6`
- `llama-index-embeddings-azure-openai==0.3.2`, `llama-index-embeddings-ollama==0.4.0`
- `llama-index-llms-azure-openai==0.3.0`, `llama-index-llms-ollama==0.5.0`
- `neo4j==5.27.0`

### 3.2 환경변수 (`.env`)

```powershell
# .env.example을 복사해서 시작
Copy-Item .env.example .env
notepad .env
```

최소 필수 키 (Azure OpenAI):

```
AZURE_OPENAI_API_KEY=sk-...
AZURE_OPENAI_ENDPOINT=https://<your-resource>.openai.azure.com
AZURE_OPENAI_API_VERSION=2024-10-21
AZURE_DEPLOYMENT_TEXT_EMBEDDING_3_SMALL=text-embedding-3-small
AZURE_DEPLOYMENT_GPT_4O_MINI=gpt-4o-mini
```

기본 Provider는 모두 `azure`. 변경하려면 §6 참조.

### 3.3 Neo4j 컨테이너 기동

```powershell
docker compose -f docker/docker-compose.neo4j.yml up -d

# 상태 확인 (running 이면 OK)
docker compose -f docker/docker-compose.neo4j.yml ps

# Neo4j Browser 접속
# http://localhost:7474   user: neo4j   pw: lgbom-poc-2026
```

`.neo4j_data/`, `.neo4j_logs/` 등에 영구 저장됨. 컨테이너 down 해도 데이터 유지.

### 3.4 데이터 배치

```
data/
├── uploads/
│   └── base_bom.xlsx          ← FAST MODE에서 자동 로드되는 기본 Base BOM
├── history/
│   ├── 변경부품Master_*.xlsx  ← 과거 개발부품 이력 (여러 파일 OK)
│   ├── 변경부품Master_*.xlsm
│   └── ...
└── ref_boms/
    └── 참고용 BOM Excel       ← enrich용 (선택)
```

`data/cache/`는 자동 생성되며 RSN LLM 추출 결과(sha256 기반)가 캐시됨.

## 4. 그래프 RAG 빌드 (최초 / 데이터 변경 시)

### 4.1 빠른 검증용 빌드 (소량 + LLM 생략)

```powershell
python scripts/build_graph_rag.py --reset --limit 5 --no-llm
```

`--reset` 기존 데이터 + vector index 정리. `--limit 5`는 history 파일 5개만. `--no-llm`은 RSN→ChangeReason 추출 생략 (LLM 호출 없음).

### 4.2 전체 빌드

```powershell
python scripts/build_graph_rag.py --reset
```

진행 단계:
1. Neo4j 연결 확인 + (--reset이면) 데이터/벡터 인덱스 삭제
2. 스키마 ensure (constraint + vector index, 현재 EMBED_DIM 사용)
3. Base BOM → Part/Assembly/PARENT_CHILD 적재 (LLM 0회)
4. History Excel → ChangeEvent/AFFECTS/Model/Region (LLM 0회)
5. RSN 자유 텍스트 → ChangeReason/Feature (LLM 사용, sha256 캐시)
6. 카운트 요약 출력

RSN 추출은 캐시되므로 두 번째 빌드부터 거의 비용 없음.

### 4.3 검증

```powershell
python scripts/verify_graph_rag.py
```

기대 출력 예:
```
# 노드 카운트
  Part                 5,432
  ChangeEvent          1,876
  Assembly               342
  ChangeReason           512
  Model                   28
  Feature                 14
  ...

# 샘플: 도어 Assembly + CAMERA Feature 경로
  [WSED7687M_DOOR] Door Assembly → Camera Module (XYZ123) ← 카메라 모듈 적용 [...]
```

Neo4j Browser에서 직접 쿼리:
```cypher
MATCH (n) RETURN labels(n) AS lbl, count(*) ORDER BY count(*) DESC;
MATCH ()-[r]->() RETURN type(r), count(*) ORDER BY count(*) DESC;
```

## 5. Streamlit 실행

```powershell
streamlit run app.py
```

기본 포트 `http://localhost:8501`.

### 5.1 FAST MODE 시나리오 (자동 검증)

1. 사이드바에서 ⚡ **FAST MODE** 토글 ON
2. 자동 주입되는 값:
   - `dev_grade = B`
   - `target_model = KWS9D7687M`
   - `change_items = ["도어에 카메라 추가"]`
   - `data/uploads/base_bom.xlsx` 자동 로드
3. "분석 시작" 클릭
4. 잠시 후 proposals 카드가 화면에 표시되어야 함:
   - L1 Assembly별 expander
   - 각 카드 내 `changed_parts` (CORE), `indirect_parts` (CASCADE)
   - 사이드바 디버그 expander에 graph metric 확인 (`graph_seed_nodes`, `traversal_depth`, `nodes_matched`)
5. 변경유형 컬럼에 `⚠️확인필요`가 없으면 Excel 다운로드 버튼이 활성화됨

### 5.2 일반 사용 흐름

1. FAST MODE OFF
2. Base BOM Excel 업로드
3. 심의회 PPT 업로드 → "모델 정보 확인" 클릭 → 추출값 검토 → "확인 후 입력값 반영"
4. "분석 시작"
5. proposals 카드 검토 (`확인필요` 행이 있으면 변경유형 확정)
6. (선택) 플로팅 챗봇으로 자연어 수정: "Shelf 제외", "Camera Module 공용으로", "Door 하위에 Gasket 추가"
7. Excel 다운로드 (변경부품리스트 + 개발부품마스터)

## 6. Provider 토글 (Azure ↔ Ollama)

`.env`에서 환경변수만 바꾸면 코드 수정 없이 전환된다.

### 6.1 LLM만 Ollama로

```powershell
ollama pull llama3.1:8b
ollama serve   # 이미 떠 있으면 생략

# .env
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_LLM_MODEL=llama3.1:8b
OLLAMA_REQUEST_TIMEOUT=120
```

영향 범위 (모두 자동 분기):
- RSN 추출 ([graph_rag/llm_extract.py](../graph_rag/llm_extract.py))
- LlamaIndex Settings.llm ([graph_rag/config.py](../graph_rag/config.py))
- feedback_chat 검토 큐 ([feedback_chat.py](../feedback_chat.py))

임베딩은 영향 없음. 그래프 재빌드 불필요. **단 RSN 캐시(`data/cache/llm_extract.sqlite`)는 모델이 바뀌어도 sha256 키가 같아 그대로 재사용됨. 새 모델 결과를 보려면 이 파일 삭제**.

### 6.2 임베딩까지 Ollama로

```powershell
ollama pull bge-m3

# .env
EMBED_PROVIDER=ollama
OLLAMA_EMBED_MODEL=bge-m3
OLLAMA_EMBED_DIM=1024
```

차원이 변경되므로 **vector index 재생성 + 노드 임베딩 재계산 필수**:

```powershell
python scripts/build_graph_rag.py --reset --reset-vector
```

| 모델 | 차원 | 비고 |
|---|---|---|
| `text-embedding-3-small` (Azure 기본) | 1536 | 영어/다국어 균형 |
| `bge-m3` | 1024 | 한국어 강함 (권장) |
| `mxbai-embed-large` | 1024 | 영어 특화 |
| `nomic-embed-text` | 768 | 가볍고 빠름 |

원복: `EMBED_PROVIDER=azure` 후 동일하게 `--reset --reset-vector` 재실행.

### 6.3 Graph RAG 자체 OFF (legacy Chroma 폴백)

문제 발생 시 즉시 우회:

```powershell
# 임시
$env:GRAPH_RAG_ENABLED="0"; streamlit run app.py

# 영구 (.env)
GRAPH_RAG_ENABLED=0
```

`app.py`의 `run_search` wrapper가 `_run_search_legacy` (Chroma 기반)로 폴백. 기존 `chroma_db/` 디스크는 보존되어 있음. 단, legacy 경로를 쓰려면 `build_rag.py`로 Chroma 인덱싱이 한 번은 되어 있어야 함:

```powershell
python build_rag.py
```

## 7. 트러블슈팅

| 증상 | 원인 / 조치 |
|---|---|
| `Neo4j 연결 실패` | `docker compose ps`로 컨테이너 확인. 포트 7687 충돌 시 다른 컨테이너 종료. 최초 기동 60초 대기 |
| `AOAI env 누락` | `.env` 키 5개 (`AZURE_OPENAI_*`) 모두 채워졌는지 |
| `Package 'llama-index-core' is not installed` | `uv sync` 재실행. `.venv` 활성화 확인 (`.\.venv\Scripts\Activate.ps1`) |
| `dimension mismatch` (Neo4j vector) | EMBED_PROVIDER/모델 바꿨는데 `--reset-vector` 누락. 빌드 재실행 |
| `db.index.vector.queryNodes` 미지원 | Neo4j 5.11+ 필요. docker-compose 이미지는 `neo4j:5.26-community` (OK) |
| RSN LLM 추출이 느림 | `--no-llm`으로 구조만 빠르게 빌드. 이후 점진 `--limit N` |
| Ollama 첫 호출 timeout | 모델 로딩 지연. `ollama run bge-m3 ""` 한 번 워밍업 후 재실행 |
| 한글 검색 누락 | [graph_rag/intent.py](../graph_rag/intent.py)의 `OBJECT_ALIASES`/`MAIN_PART_ALIASES`에 별칭 추가 |
| proposals가 빈 카드만 나옴 | (1) base_bom 업로드 확인 (2) `verify_graph_rag.py`로 ChangeEvent ≥ 100 확인 (3) FAST MODE의 target_model이 실제 데이터에 존재하는지 |
| `⚠️확인필요`가 남아 Excel 다운로드 막힘 | 의도된 동작. 해당 행의 변경유형을 확정하거나 챗봇에 "나머지 전부 추가로 확정" 명령 |
| 결과 너무 많음 / 적음 | [graph_rag/retriever.py](../graph_rag/retriever.py)의 `HOP1_MIN_RESULTS`(8), `TRAVERSAL_LIMIT`(200), `PRIMARY_DOC_CAP`(60) 튜닝 |
| 사이드바 디버그 메트릭에 graph 키가 없음 | `GRAPH_RAG_ENABLED=0`이거나 graph_rag 호출이 예외로 폴백 중. `st.session_state["debug_err"]["graph_rag"]` 확인 |
