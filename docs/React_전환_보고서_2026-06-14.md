# Streamlit → React 전환 보고서

작성일: 2026-06-14

## 1. 배경 — 진짜 문제 (사용자 피드백)

> "변경부품이나 전체 마스터가 그냥 **테이블로 쭉 나열**되어 있어서, 어떤 부품이
> 변경된다는 건지 알기가 너무 어렵다. **미정 부품**이 어떤 건지도 알려줘야 피드백이 쉽다."

기존 Streamlit UI(`src/dev_parts_backend/ui/streamlit_app.py`)는 모든 화면이 `st.dataframe`
평면 테이블이라, **무엇이 바뀌는지 한눈에 안 보이고** 미정(TBD) 부품이 표 속에 묻혔다.
검색·merge 알고리즘 문제가 아니라 **표현(UX) 문제**였다.

## 2. 결정

- **Streamlit → React(Vite + TypeScript)** 전환.
- 핵심 화면은 평면 테이블이 아니라 **변경 카드 중심**: 변경 1건 = 카드 1장,
  `현재 → 변경 후` diff + 후보 라디오 선택 + 변경 종류/미정 배지.
- 범위: **전체 기능 패리티**(Streamlit 3탭 대응).
- 백엔드(FastAPI)는 그대로. React는 기존 API를 그대로 소비.

## 3. 구현한 것

### 백엔드(최소 변경)
- `api/main.py`에 **CORS 미들웨어** 추가(localhost 전 포트 허용). React dev 서버 호출용.
- `cli.py`에 **`devparts web`** 명령 추가(Vite dev 서버 실행).

### 프론트엔드 (`frontend/`)
- Vite + React 18 + TypeScript. 의존성은 react/react-dom + vite/tsc만(가볍게).
- 타입드 API 클라이언트(`api.ts`), 탭 간 공유 상태(`store.tsx`).
- **변경 카드**(`ChangeCard.tsx`): 종류 배지(변경/추가/삭제), base→after diff, 변경점·사유,
  후보 라디오(★1=추천, score 표시), action 선택, add 시 연동부품 번들, 연관부품 보기.
- **반영 결과**(`BomResultView.tsx`): 변경된 행만 모아서 표시, **미정(TBD) 보라색 배지로
  강조** + 별도 경고 배너, 변경/추가/삭제/미정 칩 필터.
- 3탭: ① 변경 입력·추천 ② BOM 반영(카드) ③ 데이터 확인.

### 변경 종류 판정 규칙 (`util.ts: rowKind`)
```
new_part_no == "TBD" 또는 applied_action == "propagated_change"  -> 미정(TBD)
applied_action == delete                                         -> 삭제
applied_action == add / add_bundle                               -> 추가
applied_action == change / subtree*                              -> 변경
그 외                                                            -> 변경없음(접힘)
```

## 4. 실행

```powershell
uv run devparts serve     # 백엔드 :8000
uv run devparts web       # 프론트 :5173 (저장소 루트에서)
```
접속 http://localhost:5173 — Vite가 `/api/*`를 FastAPI로 프록시.

### 변경 종류 판정(트리 포함, master 산출)
```
applied_action change/subtree → Change   |  add/add_bundle → New  |  delete → Delete
propagated_change / new_part_no==TBD      → Change(상위 재발행)
변경점 트리 안의 재사용 부품(anchor의 조상·후손) → Common
변경점과 무관한 가지                       → 제외
```
