## 1. 변경점 추출 — 추출 결과 사전 확인 + 최상위 토글  ✅ **완료 (2026-06-15)**

> **구현 결과**
> - **ⓐ 추출 검수 단계 신설**: PPTX 추출 직후 `① 추출 검수` 화면에서 원본 표를 **편집 가능한 그리드**로 보여줌(No/Lev/Part Name/Base·New P/No/Qty/상세변경점). 셀 수정·**행 삭제**·**모듈별 행 추가** 가능. **"검수 완료 →"** 누르기 전까지는 TBD 빨간 표시/자동 분류를 적용하지 않음(= 빨간 물결 이전 단계). 검수 완료 시점에 공용=base 재사용, 신규=TBD 자동 분류.
> - **ⓑ 최상위(모듈) 토글·기본 접힘**: 모듈 그룹마다 토글 추가, **처음엔 전부 접힘**. 접힌 헤더에 신규/변경/공용/TBD 미니 카운트 + 요약 한 줄 노출 → 펼치지 않아도 내용 파악. `전체 펼치기/접기` 연동.
> - **ⓑ-2 모듈 내부 부모-자식(레벨) 토글** (2026-06-15 추가): 모듈 안에서도 `.1` 부모 카드를 접으면 그 아래 `..2`/`...3` 자식들이 묶여 숨겨짐(프리오더 깊이 기반). 접힌 부모엔 `+N 하위` 표시. 자식 있는 카드에만 ▾/▸ 노출.
> - **ⓒ 변경점 요약 문구 활용**: 백엔드 `bom_table._slide_summary`가 슬라이드 하단 `※ 내용 요약 ①②③ …`을 모듈별로 추출 → 응답 `summaries`. 검수/작성 화면에서 모듈마다 **"변경점 요약"** 박스로 표시. (퀵존 10개 모듈 중 7개에서 요약 추출 확인)
> - 검증: tsc 통과, vite 빌드 OK, API `extract-bom` → records 253 / summaries 7, UI 200. 릴리스 패키지 동기화 완료.

## 2. Base BOM 업로드 순서 — PPT + Base BOM 동시 업로드  ✅ **완료 (2026-06-15)**

> **구현 결과**: ① 변경점 작성 탭 상단을 **2열 업로드(① 심의표 PPTX / ② Base BOM)** 로 재구성 → PPT와 Base BOM을 **같은 단계에서 함께 업로드**. 5번(store 영속화) 덕분에 ①에서 올린 Base BOM이 **②까지 그대로 유지**됨(ApplyTab에 "✓ Base BOM N행 연결됨" 표시, 거기서 교체도 가능). 퀵존은 PPT에 품번이 있어 Base BOM 생략 가능(선택)임을 안내.

| 구분 | 내용 |
|---|---|
| **요청** | 원래 기존 품번 파악을 위해 **Base BOM이 먼저** 필요 → **변경점용 PPT와 Base BOM을 함께 업로드**하는 구조가 맞음(이전 코드들처럼). |
| **배경** | 퀵존은 등급심의 자료 **자체에 기존 품번이 포함**되어 PPT만으로 변경부품 추출이 가능한 특수 케이스. 다른 자료는 Base→신규 흐름이 불명확. |
| **현재 상태** | 현재는 ① 변경점 작성 → ② BOM 반영에서 Base BOM을 ②에서 업로드하는 흐름. |
| **대응 방향** | Base BOM을 ① 단계에서(또는 동시에) 받도록 흐름 재배치 검토. 5번(탭 간 상태 유지)과 함께 묶어서 설계. |

## 4. BOM 반영결과 — 트리 구조로 전체 부품 표시  ✅ **완료 (2026-06-15)**

> **구현 결과**: `BomResultView`에 **「전체 트리 / 변경만」 뷰 토글** 추가(기본=전체 트리). 전체 트리는 `bom_depth` 기반으로 전체 부품 구조를 들여쓰기·중첩 렌더링하고, 자식 있는 노드마다 **▾/▸ 접기**(접으면 `+N 하위 · 변경 M` 요약). 변경/추가/삭제/미정은 좌측 컬러바+배지로 강조, 변경없음(keep)은 흐리게. `전체 펼치기/접기` 지원. (검증: 실제 apply 681행, 깊이 1~6레벨 정상 중첩)

| 구분 | 내용 |
|---|---|
| **지적** | 현재 화면은 엄밀히는 **BOM 반영 결과가 아니라 "변경부품 리스트"**에 가까움. |
| **요청** | 실제 BOM/개발부품마스터 반영 결과라면 **해당 제품의 전체 부품 구조**가 보여야 함 → **트리 형태**로 구성, 토글로 펼쳐가며 검토. (빨간 꺾쇠 ▸ 아이콘이 그 의미) |
| **추가** | 변경점 작성 탭의 **Master CSV도** 실제 마스터보다 변경부품 리스트에 가까움(3번과 연결). |
| **현재 상태** | `BomResultView`가 플랫 리스트 + 색구분. Level은 있으나 트리 들여쓰기/접기 미흡. |
| **대응 방향** | Level(Lev) 기반 트리 렌더링 + 상위 노드 토글. 변경 없는 부품도 전체 표시. **공수 큼(핵심 UI 작업).** |

## 5. 변경점 수정 편의성 — 탭 이동 시 상태 유지  ✅ **완료 (2026-06-15)**

> **구현 결과**: 변경점 작성 탭의 작업 상태(추출 행·검수/작성 단계·요약·파일명)를 **컴포넌트 로컬 state → 전역 store로 승격**. 이제 ②BOM 반영 등 다른 탭으로 갔다 와도 **초기화되지 않고 그대로 유지**됨. 검토 중 수정이 필요하면 ①로 돌아가 카드 수정 후 다시 「② BOM 반영으로 보내기」하면 됨. (※ BOM 결과 화면 인라인 수정은 6·7번 편집 메커니즘과 묶어 후속 처리)

| 구분 | 내용 |
|---|---|
| **지적** | BOM 반영 결과 검토 중 수정/피드백이 필요한데, **변경점 작성 탭으로 이동하면 초기화**되어 수정이 어려움. |
| **요청** | (a) 탭을 오가도 **작성 내용 유지**, 또는 (b) **BOM 반영 결과 화면에서 직접 변경점 수정** 가능. |
| **현재 상태** | `masterChanges`는 store에 저장되나, ① 탭의 카드 입력 상태(`Row[]`)는 재추출 시 초기화될 수 있음. |
| **대응 방향** | ① 탭의 행 상태도 store로 승격(추출 결과 persist) → 탭 왕복해도 유지. 가능하면 ② 화면 인라인 편집. **상태관리 리팩터(중간 공수).** |

## 6. BOM 추출 결과 — Level 수정 / 상위 부품 지정  ✅ **편집기능 완료 (2026-06-15)**

> **구현 결과**
> - **6A Level 수정**: 검수 그리드에서 Lev 직접 입력 + 작성 카드에 **"Level/상위 부품 지정"** 패널 추가(`.1`/`..2` 형식). lev는 `buildMaster`로 `bom_level`에 실려 ② BOM 트리 깊이에 그대로 반영됨.
> - **6B 상위 부품 지정**: 작성 카드에서 **상위 부품 드롭다운**으로 선택 → 해당 부품의 자식 레벨(`makeLev(parentDepth+1)`)로 바뀌고 부모 바로 뒤로 이동(드래그앤드롭 대신 "상위 부품 선택" 방식 — 피드백의 차선책 채택).
> - **순서 변경(#)**: 검수 그리드 각 행에 **↑/↓ 이동** 버튼.
> - ※ "BOM 추출 결과에서 일부 부품이 최하단 분리" 표시는 apply 측(매칭 실패분 말미 배치) 원인으로 별도 조사 필요 — 현재는 ①에서 lev/상위 지정으로 사용자가 교정 가능.

| 구분 | 내용 |
|---|---|
| **버그성 지적** | 변경점 작성 단계에선 하위 부품으로 정상 구성됐는데, **실제 BOM 추출 결과에선 일부 부품이 최하단에 분리**되어 표시됨. |
| **요청 A** | Quick Zone Drawer처럼 **신규 부품이라 PPT에서 Level 추정 불가**한 경우 → 변경점 작성 탭에서 **품번 수정과 같은 방식으로 Level도 수정** 가능하게. |
| **요청 B** | 특정 부품의 하위로 넣어야 하는 경우 **상위 부품 지정 기능** 필요. <br>· 1순위: **드래그 앤 드롭**으로 위치 변경 <br>· 차선: **상위 부품명 입력**으로 해당 하위로 이동 <br>· 순서는 **`#` 값 수정**으로 조정 |
| **현재 상태** | Level은 PPTX 파싱값 그대로. 사용자 편집/재배치 수단 없음. 분리 표시 버그 원인 조사 필요. |
| **대응 방향** | (버그) 매칭 실패 부품의 부모 귀속 로직 점검. (A) Level 인라인 편집 추가. (B) 상위 지정 — DnD는 공수 큼, 우선 "상위 부품명 입력" 방식부터. |

## 7. [추가 구두 피드백] 변경부품 리스트에 원하는 위치로 수동 부품 추가  ✅ **완료 (2026-06-15)**

> **구현 결과**: 검수 그리드 각 행에 **＋(아래에 행 삽입)** + 모듈별 "＋ 행 추가" → **원하는 위치에 PPT에 없는 부품을 직접 추가**. 추가 행은 위 행의 모듈·Lev 상속.
> **추가 (2026-06-15)**: ② 작성(카드) 단계에도 **"＋ 이 모듈에 부품 추가"** 버튼(신규=TBD 기본) → 카드 화면에서 바로 부품 추가 가능.
> **드래그 앤 드롭 (2026-06-15)**: 작성 카드에 **드래그 핸들(⠿)** 추가 → 카드를 잡고 **위/아래로 끌어 이동**(다른 모듈로도 이동). 드롭 위치는 파란 선으로 표시. 입력칸과 충돌 안 나게 핸들로만 드래그.
